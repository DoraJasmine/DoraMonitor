# 已知限制与注意事项

本文记录当前实现的真实边界，帮助用户判断数字能否用于对账、容量规划或公网部署。
它不是未来功能承诺；具体算法仍以对应文档和代码为准。

## 1. 服务与部署

- DoraMonitor 是**单用户本机应用**，没有登录、权限体系或多租户隔离。默认回环监听和写请求
  Origin 校验不能替代公网鉴权；不要直接以 `0.0.0.0` 或 `::` 暴露到不可信网络。
- Node 18 可运行，但 ZCode/QoderCN 在没有 `node:sqlite` 时需要额外安装 `sqlite3` CLI。
  推荐 Node 22.15+；旧版的压缩会话由纯 JS `fzstd` 回退处理。
- Windows 提供隐藏计划任务；Linux 安装器可选注册 systemd 用户服务。其他 init 系统需自行管理后台进程；
  macOS 尚未提供一键安装或登录自启脚本。
- 源码部署需要 devDependencies 来构建前端；npm 包则已带 `dist/`，普通安装不需要前端工具链。

## 2. 用量统计

- 统计准确性受各工具本地格式限制。路由码或新模型尚未映射时会保留原名称，费用可能使用
  K2.6 参考价并标记“估算”。
- 原始请求记录在本机内存中只保留最近约 30 天且最多 20,000 条；更早用量由日桶参与统计。
  因此“最近请求”和分钟级区间不能代表完整历史，但日／月／全部总量不受这一驻留上限影响。
- Gemini CLI 必须启用本地 OpenTelemetry 文件导出。其数据没有项目维度，导出文件超过 32 MiB
  时只读取开头部分；应在 Gemini 侧轮换文件，避免遗漏较新的数据。
- 各工具复制、fork、归档的去重规则不同，依赖其记录 ID 或值签名。极端情况下，同值且同时间的
  两次真实调用可能被保守去重；无时间戳记录不会按值签名去重。

各工具的具体口径见[用量统计与数据源](./tools.md)。

## 3. 金额与价目

- “估算费用”是按公开 API 刊例价计算的等效价值，不是订阅账单、实际扣费或套餐剩余金额。
- 内置价格需要随官方变化维护；DeepSeek 法定节假日表目前只覆盖 2026 年，其他年份仅按星期和时段判断。
- 未识别模型使用 K2.6 参考价；没有单独公开价格的模型可能有映射或估算标记，不应把数字用于精确对账。
- 官方未单列缓存写入价不等于免费；未分类的双档写入按简单平均估算，已知 TTL 才按对应档精确计算。

详见[计价体系](./pricing.md)。

## 4. 官方额度与等效额度

- 官方额度依赖本机登录态和上游接口。接口不可用、凭据过期或快照过旧时，页面应显示不可用或旧快照，
  不会伪造零值。
- 等效额度由额度百分比和本地用量反推，Kimi 的整数百分比粒度、跨客户端消耗、peer 同步延迟都会带来误差。
- 置信度是 0–100 的数据质量评分，不是统计概率；达到展示门槛也不表示厂商确认了上限。
- 额外 Kimi 账号目前只开放官方额度、采样和历史；账号用量归属未可靠映射前，不提供等效额度估算。
- 长程估算已退役；兼容 API 中的旧结果不代表仍在持续更新。

详见[额度估算](./quota-capacity-estimation.md)及其“目前的不足”。

## 5. 多设备同步

- 同步需要共享存储，不是设备间点对点连接。普通看板只读缓存；共享存储不可用时会继续显示旧对端数据。
- 设备名必须唯一，同名且安装 ID 不同会被拒绝，不会自动合并或覆盖。不要把 `device-id` 复制到另一安装。
- 对端数据是日汇总和额度元数据，不是完整会话。旧版本对端缺少分钟桶或水位线时，额度估算会降置信度或暂不计算。
- SSH 要求预先配置免密登录；WebDAV 密码在本机配置文件中明文保存，依赖操作系统文件权限保护。

详见[多设备同步](./sync.md)。

## 6. 开源与发布注意

- `npm pack --dry-run` 只证明当前文件白名单和构建可打包，不代表 npm 账号、名称权限或正式发布已完成。
- 公开仓库前应检查**整个 Git 历史**，而不仅是当前工作区。曾提交过的凭据即使后来删除，也必须轮换并清理历史。
- 本机 `~/.doramonitor/`、日志、待办、启动器生成物和同步配置不应进入提交或发布包。
- 发布 npm 与公开 GitHub 仓库是两个独立操作，均需维护者明确执行；脚本不会自动完成它们。
