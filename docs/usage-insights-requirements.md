## 1. 背景与目标

dsh-all-usage 在"多维用量分析"上做得比较成熟:工作区维度统计、趋势图点击下钻当日明细、模型用量按模型/供应商分维度查看、统一的筛选条与导出。DoraMonitor 目前有能力相近的数据底座(逐请求记录 + 日桶聚合),但在交互维度上缺少这三块。

本需求文档定义四组增强:

| 编号 | 需求 | 来源灵感 |
| --- | --- | --- |
| R1 | 视觉与设计风格升级 | dsh-all-usage 总览页(hero 大数字卡、彩色统计卡、胶囊图例、统一筛选条) |
| R2 | 工作区维度用量统计 | 各工作区总量卡、工作区分布热力图、工作区别名、已删除归并 |
| R3 | 趋势/热力图点击查看当日明细 | "点击数据点查看当日明细",单日视图填充小时粒度 |
| R4 | 模型用量明细按模型查看 | 环形占比图 + 模型列表,混合查看/按模型/按供应商三态切换 |

目标用户:本机使用多工具(Kimi Code / Codex / Claude Code / ZCode 等)并希望回答"我的 Token 花在哪个项目、哪个模型、哪一天"的个人开发者。

## 2. 现状盘点(差距基线)

| 能力 | 现状 | 差距 |
| --- | --- | --- |
| 逐请求明细 | 有,但仅保留近期窗口(`RECORD_WINDOW_DAYS` + `RECENT_LIMIT=500`,见 `src/aggregate.js:784`、`src/collect.js:21-22`),无查询 API | 需要分页明细端点 |
| 工作区/项目维度 | 采集器记录带 `project` 字段(claude-code/codex/omp/dsh/qoder 为真实 cwd;kimi-code 为 `wd_*` 目录 ID;zcode/gemini 无),但**聚合层完全没有 project 分组**(桶 schema 为 day×tool×model×rateKey,`src/buckets.js:14`) | 数据层半就绪,聚合与前端全缺 |
| 趋势图交互 | `DailyBars` 仅 hover tooltip,无点击 | 需要点击下钻 |
| 热力图交互 | `Heatmap` 纯展示,仅原生 title | 需要点击下钻 |
| 模型明细 | 模型表行点击 = 切到 "all" + 过滤最近请求表,无独立明细视图 | 需要专门的模型明细视图 |
| 筛选体系 | 顶部时间范围 + 最近请求表内模型下拉 | 需要全局统一筛选条(时间×工作区×模型) |
| 导出 | 无 | 需要 CSV 导出 |
| UI 风格 | 暗色 teal 主题、shadcn/ui 组件、单列卡片流(`web/src/styles.css:19-49`) | 风格基础好,吸收参考项的层级与信息密度设计 |

## 3. 需求详述

### R1 视觉与设计风格升级

从 dsh-all-usage 吸收的设计要素(保持 DoraMonitor 现有 teal/暗色主题与 shadcn 组件体系,不推倒重来):

1. **Hero 总量卡**:页面顶部一张大卡,左侧超大数字(当前范围总 Token + 中文单位副行"xx 亿"),右侧并排"总请求数 / 估算成本"两个子卡;替代现有 8 张等权重 KPI 卡中的头部(其余 KPI 收敛为次级一行)。
2. **彩色语义统计卡**:关键衍生指标用整卡着色强调(如缓存命中率绿卡、连续使用橙卡、账户余额蓝卡),DoraMonitor 对应物为缓存命中率、额度剩余、连续使用天数。
3. **统一筛选条**:时间范围(今天/7 天/30 天/90 天/全部/自定义)与工作区、模型两个维度下拉置于同一行,筛选状态持久化到 localStorage;所有区块(统计卡、趋势、热力图、模型、明细)共享同一筛选上下文。
4. **胶囊图例**:趋势图图例改为可点击的彩色 pill(点击隐藏/显示序列),现有 DailyBars 已有等价能力,样式对齐。
5. **口径说明条**:统计卡下方一行浅色说明,解释"总 Token = 普通输入+模型输出+缓存读取+缓存创建,费用为刊例价估算",降低误读。
6. **导出按钮**:筛选条右侧"导出数据"按钮,导出当前视图 CSV。
7. **扫描健康行**:顶部一行灰字展示"已更新时间 · 记录数 · 解析错误数",对应现有 footer 元数据,前置提升可见性。

验收:
- [ ] 用量页顶部出现 hero 卡与统一筛选条,原 8 张 KPI 卡收敛且信息不丢失;
- [ ] 筛选状态刷新后保留;
- [ ] 中英文文案齐备。

### R2 工作区维度用量统计

1. **工作区归一化**:以"工作区"为一等实体,`project` 字段归一化为稳定 workspace key + 显示名:
   - claude-code/codex/omp/dsh/qoder:cwd 即工作区;
   - kimi-code:`wd_*` ID 通过 `src/sessions.js` 已有的 `state.json workDir` 映射为真实路径;
   - zcode/gemini:无 cwd,归入"未知工作区";
   - 支持用户编辑**工作区别名**(存本机 `~/.doramonitor/config.json`,仅影响显示);
   - 被删除/不存在目录的工作区历史保留,汇总为"已删除/已归档"一行,不丢数据。
2. **各工作区总量卡**:统计卡区一张"各工作区用量"卡,列出 Top N 工作区(彩色圆点 + 名称 + Token + 占比),其余合并为"其他 N 个",点击工作区可筛选全局。
3. **工作区筛选**:统一筛选条中新增工作区下拉,与时间/模型正交组合。
4. **工作区明细表**:明细区新增"工作区统计"页签,列出工作区 × 时间范围的请求数、四项 Token、命中率、费用。
5. **隐私边界**:工作区(项目路径/别名)**仅在本地展示**,不进入多设备同步载荷,维持"不同步项目名"红线(见 `docs/sync.md`);同步摘要中的日桶若新增 project 维度,需以哈希或省略方式处理,默认不同步 project 维度。

验收:
- [ ] 用量页可按工作区筛选并看到各工作区用量排行;
- [ ] kimi-code 会话能归到真实工作目录;zcode 记录归入"未知工作区"且不影响其他维度;
- [ ] 重命名别名后所有视图即时生效;删除工作区目录后历史统计不变;
- [ ] 同步载荷不含项目路径明文。

### R3 趋势/热力图点击查看当日明细

1. **点击下钻**:趋势图(`DailyBars`)与热力图(`Heatmap`)的每个数据点/格子可点击(键盘可达:方向键移动 + 回车确认),打开**当日明细弹层**。
2. **当日明细弹层**内容:
   - 当日四项 Token / 请求数 / 费用 / 命中率汇总;
   - **小时粒度曲线**(0-23 时分布)——对标 dsh "单日 scope 填充 hourly";
   - 当日按模型、按工作区的分项表;
   - 若当日落在逐请求记录窗口内,追加**逐请求列表**(时间、模型、四项 Token、费用,复用现有最近请求表组件);窗口外仅提供聚合分项,并明确提示"逐请求明细仅保留近 N 天"。
3. **数据端点**:新增按日查询端点(scope = 单日 + 当前工作区/模型筛选),一次返回日汇总、hourly、分项;单日 hourly 从逐请求记录可得,窗口外日期 hourly 不可得则省略该区块。
4. 趋势点数沿用封顶策略(≥180 点自动降粒度),弹层标题显示准确日期。

验收:
- [ ] 点击趋势图任一天与热力图任一格均能打开当日明细;
- [ ] 窗口内日期可见小时分布与逐请求列表,窗口外日期可见按模型/工作区分项且无报错;
- [ ] 弹层内可继续按模型过滤;Esc/点击遮罩关闭。

### R4 模型用量明细按模型查看

1. **模型明细区**重构为:左侧**环形占比图**(中心显示当前范围总 Token),右侧模型行列表(色点 + 图标/名称 + Token + 费用 + 占比),超出的模型归并为"其他 (N)"。
2. **三态切换**:`混合查看`(默认,按工具×模型)/ `按模型`(跨工具合并同名模型,依赖现有 `model-identity.js` 归一)/ `按供应商`(按 modelProvider 汇总)。
3. **点击模型行** → 打开该模型明细弹层:当前范围内该模型的请求数、四项 Token、命中率、费用、按日趋势,以及逐请求列表(记录窗口内,分页加载)。
4. 模型表与环形图联动 hover;保留现有"官方价/估算价"徽标。

验收:
- [ ] 三态切换数值自洽(按模型合计 = 混合合计);
- [ ] 点击模型可看到该模型逐请求明细并可分页;
- [ ] 未识别模型显示中性名称,不做无依据推断。

## 4. 非功能需求

1. **性能**:新增端点不得触发全量重扫,全部从日桶/记录缓存读取;明细弹层首屏 < 300ms(本机);分页加载逐请求明细。
2. **隐私**:不新增任何提示词/正文/凭据读取;项目路径仅本地;导出 CSV 由用户显式触发。
3. **兼容**:任一工具无工作区数据不影响其他工具;`DORAMONITOR_DISABLE_BUCKETS=1` 回退路径可用。
4. **i18n**:全部新文案 zh/en 双语;日期口径跟随现有本地时区规则。
5. **约束**:本期不引入数据库与重型前端依赖(延续 PRD 5.2 节),图表用现有自绘组件扩展。

## 5. 不做什么

- 不做 dsh-all-usage 的 DeepSeek 账户余额、峰谷计价、节假日谷价(DoraMonitor 已有自己的计价体系,见 `docs/pricing.md`);
- 不做多设备 project 维度同步(本期);
- 不做请求日志的 turn/step 层级展开(部分工具源数据没有该粒度)。
